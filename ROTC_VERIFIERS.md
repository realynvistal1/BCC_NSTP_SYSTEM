ROTC attendance verification
============================

Battalion 1 requires a **male** approved Advance Course verifier; Battalion 2 requires a **female** approved Advance Course verifier. Medics, HQ and MP can use either. Candidate choices, assignment validation and ongoing access checks enforce this rule. Manual test account details are in `ROTC_TEST_ACCOUNTS.md`.

MI selection is limited to **1–15** and is populated only from existing regular ROTC attendance sessions matching the selected MS level and school year. IN/OUT choices are limited to the types already created for that MI. The server rejects assignments for uncreated sessions. Create the attendance session before assigning its verifier.

New assignments require an **MI number** and **IN/OUT type**. These restrict both the visible submissions and updates, and appear in the Director's and verifier's assignment labels. The same group and cycle can have different verifiers for different MIs or IN/OUT. Assignments created before this upgrade keep their previous all-session access and are labeled **All MIs (existing assignment) / All types**; revoke and replace those assignments to narrow their scope.

Special Platoon is also supported. In ROTC Verifiers, choose **Assignment Type → Special Platoon**, then **Medics**, **HQ**, or **MP**, and the target MS level and school year. An approved Advance Course student verifies that unit's submitted attendance. Unit membership is checked against the student's saved approved enrollment assignment. The Special Platoon roster has an assignment shortcut. Re-run the migration when upgrading from the regular-platoon-only version; existing assignments are preserved.

Run `npm run db:migrate:rotc-verifiers` against each database before starting the updated server. The local workspace database has already been migrated. Database setup also includes the new tables.

The NSTP Director opens **ROTC Verifiers**, selects an approved Advance Course student, then assigns a battalion, company, platoon and enrollment cycle (MS level and school year). The verifier's own enrollment level does not need to match the platoon's level. Assigning a different student to the same platoon and cycle replaces its previous verifier; Revoke Access disables the assignment immediately.

The student keeps their usual student login. **My Assigned Attendance** is available in the ROTC student menu, with a dashboard shortcut for Advance Course students. A new or changed eligible assignment pops up while the student portal is open, showing the group, cycle and MI IN/OUT. The verifier sees the full approved roster for the saved enrollment group and cycle, including Present, Late, Absent and Unmarked students. They can confirm missing submissions with a required reason after the session opens. They cannot create a session, verify themselves, or access CWTS or Advance Course sessions. Eligibility and scope are checked again by the server on every update.

Each update requires a reason and saves the previous status, new status, verifier and timestamp in an audit log. The recorded Present/Late/Absent status is effective immediately; there is no pending verification state or additional Director approval. Saving explicitly reports a newly recorded false-attendance offense, an already recorded offense without duplication, a removed offense after correction, or no punishment offense. Updated records show **Updated by** and the timestamp. The Director can review the latest 200 changes in ROTC Verifiers and receives an attendance update notification.

Existing-record verifier forms include `expected_version`. Under the transaction lock, saving checks it against the current `record_version`; verifier and staff corrections increment the version. An outdated or legacy form receives HTTP 409 and cannot modify attendance, offenses or the log. The dialog disables saving and offers **Refresh and review**. Refresh reloads assignments and the selected roster, preserves the selected assignment if still active, falls back to a current assignment if revoked, and remains available when there are no assignments. Older requests cannot repaint a newer refresh.

The correction updates the same record used by the Director, ROTC admin attendance summary, student history and attendance totals. Open Director and admin summary pages refresh every 20 seconds, preserving selected filters. Student history and dashboard counts also refresh through the student alert check. New offense warnings and assignment notifications are checked every 20 seconds and when returning to the student tab. A student who is offline sees an unacknowledged warning on their next visit. Automatic refresh pauses while Director/admin dialogs are open.

Punishment offenses apply only to false Present claims: a student submitted Present, but physical verification finds them absent from the required class area. Student Present submissions are tracked with `claimed_present`; confirming them as Absent sets `false_present`. Automatic absences, missing submissions marked Absent and staff-created Present records do not create punishment offenses. Each false claim contributes once, capped at the existing two-offense threshold. Correcting a mistaken false-claim finding to Present/Late recalculates the total. Repeated saves preserve settlement; a newly confirmed false claim resets settlement.

The assigned roster includes approved students with no submission as **Unmarked**. The verifier must explicitly choose Present/Late/Absent and supply a reason. Creating that record uses the same group, cycle, MI/type, self-verification and eligibility checks as corrections. Sessions must have opened. If attendance is submitted concurrently, the verifier must refresh and review it before editing. Creation and corrections commit the record, audit entry and offense together.

Session closing commits missing Absent records and `attendance_finalized_at` in one transaction, without changing punishment offenses. Failures roll back and retry on the next attendance refresh. Old closed sessions without a completion marker are repaired on refresh. Run `npm run db:migrate:rotc-verifiers` before running this version; the migration adds the completion marker, false-claim tracking fields and record version. It has been applied to the local database. Existing GPS Present records and GPS records with a logged prior Present status are used to identify historical claims; missing submissions are never classified as claims.

Run `npm run verify:rotc-verifiers` on a development database. It creates isolated temporary students, enrollment schedules and attendance records, verifies allowed and blocked updates, then removes its fixtures. No real student is assigned by this script.

Run `node scripts/verify-verifier-refresh-ui.js` for assignment-refresh, outdated-form review and stale-request UI checks without database fixtures.
